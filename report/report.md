# CP1-отчёт: SMS Spam Detection

## 1. Постановка задачи

Цель проекта - по тексту SMS определить, относится ли сообщение к спаму. Это бинарная классификация с классами `ham` и `spam`.

Основная метрика - `F1` по классу `spam`. Простая `accuracy` здесь не очень честная: в корпусе обычных сообщений существенно больше, чем спама, и модель может выглядеть сильной, просто редко предсказывая spam. Для прикладного фильтра важен баланс: не пропускать рекламные/мошеннические сообщения, но и не блокировать нормальные SMS. Поэтому в таблицах дополнительно считаются `precision_spam` и `recall_spam`.

## 2. Данные

Используется SMS Spam Collection: открытый корпус SMS-сообщений, собранный для исследований spam filtering. Датасет доступен в UCI и на Kaggle.

Сырой корпус содержит 5 574 строки. После удаления точных дублей по паре `label + message` осталось 5 158 сообщений:

| Класс | Количество |
|---|---:|
| ham | 4 516 |
| spam | 642 |

Ограничение датасета намеренно вынесено отдельно: корпус меньше формального порога в 10 000 строк и в сыром виде имеет две колонки. Проект и датасет были предварительно согласованы, поэтому на CP1 я не маскирую это расширением “для галочки”. Вместо этого задача трактуется как текстовая классификация: после TF-IDF одно текстовое поле превращается в тысячи признаков, а поверх текста добавляется небольшой набор понятных ручных признаков.

## 3. Обработка и признаки

Пайплайн обработки находится в `src/data.py` и `src/features.py`.

Что сделано:

- загружен исходный архив `sms_spam_collection.zip`;
- оставлены две исходные колонки: `label`, `message`;
- метки приведены к нижнему регистру и закодированы в `target`: `ham = 0`, `spam = 1`;
- удалены пустые сообщения и точные дубли;
- добавлены ручные признаки поверх текста.

Ручные признаки:

| Признак | Зачем нужен |
|---|---|
| `message_length` | спам часто длиннее обычных коротких SMS |
| `word_count` | грубая оценка структуры сообщения |
| `digit_count` | промокоды, номера, суммы и телефоны часто встречаются в spam |
| `uppercase_count`, `uppercase_ratio` | агрессивный uppercase характерен для рекламных сообщений |
| `exclamation_count`, `question_count` | простая эмоциональная пунктуация |
| `special_char_count` | валюты, проценты, служебные символы |
| `has_url` | ссылки - сильный сигнал для спама |
| `has_phone` | номера телефонов и короткие номера часто встречаются в CTA |
| `has_currency` | денежные обещания и призы |
| `cta_word_count` | слова действия: `call`, `txt`, `claim`, `free`, `win`, `urgent` |

## 4. Разбиение данных

Используется стратифицированный split `70/15/15`: train, validation, test. Seed зафиксирован в `src/config.py`.

Важно для leakage: `CountVectorizer` и `TfidfVectorizer` находятся внутри sklearn pipeline и обучаются только на train-части. Validation и test не участвуют в построении словаря и расчёте IDF.

## 5. Baseline и первые эксперименты

На CP1 проверены простые модели, которые дают адекватную отправную точку для CP2:

| Модель | Split | Accuracy | Precision spam | Recall spam | F1 spam |
|---|---:|---:|---:|---:|---:|
| `CountVectorizer + MultinomialNB` | test | 0.979 | 0.966 | 0.866 | 0.913 |
| `TF-IDF + LogisticRegression` | test | 0.961 | 0.986 | 0.701 | 0.819 |
| `TF-IDF + LinearSVC` | val | 0.988 | 1.000 | 0.906 | 0.951 |
| `TF-IDF + LinearSVC` | test | 0.978 | 0.955 | 0.866 | 0.908 |
| `TF-IDF + ручные признаки + LogisticRegression` | test | 0.983 | 1.000 | 0.866 | 0.928 |

На validation лучший результат показал `TF-IDF + LinearSVC`: `F1_spam = 0.951`. На test лучше выглядит логистическая регрессия с ручными признаками: `F1_spam = 0.928`. Для CP1 это нормальная ситуация: test не используется для выбора модели, он только показывает, что baseline уже работает существенно лучше тривиального решения.

## 6. Что важно вынести в CP2

На CP2 нужно расширить именно экспериментальную часть:

- добавить 4-5 моделей и ансамбли;
- сделать перебор гиперпараметров для TF-IDF и моделей;
- проверить устойчивость результата через cross-validation;
- отдельно сравнить модели с ручными признаками и без них;
- добавить интерпретируемость: важные n-граммы, коэффициенты линейных моделей, ошибки на false positive/false negative.

К CP1 готова база: данные воспроизводимо собираются, признаки создаются кодом, baseline обучается одной командой, метрики сохраняются в `report/cp1_results.csv`.
